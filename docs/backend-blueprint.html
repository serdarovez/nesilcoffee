NesilCoffee Backend Blueprint

Turning a fully static five-language marketing site into a database-backed product with a Russian admin dashboard — without changing a single pixel of what visitors see on day one.

Next.js 16.3.1 PostgreSQL Prisma unstable_cache + revalidateTag argon2 sessions sharp nodemailer / Gmail SMTP WhatsApp Cloud API PM2 + nginx + certbot

Scope

What becomes editable, and what deliberately stays in the message files.

Database-backed & editable

  • Products — 16 across 4 categories
  • Categories — full CRUD, drives page sections
  • Home carousel — pick products, drag to reorder
  • Products hero carousel — 3 full-bleed slides
  • Team members
  • FAQ items
  • Certificates
  • Site contact details — phones, address, socials
  • Submissions log — contact + orders

Stays in message files

  • About page — welcome, geography, history, quality, experts
  • Production process — 4 blocks
  • Home hero, office format, searched-for sections
  • Navigation, CTA and form labels
  • Product detail pages — slug reserved, pages deferred
  • Order pricing & fulfilment pipeline — site is quote-based B2B

Decisions

Thirteen forks, each resolved with its reasoning. This is the contract the build follows.

Architecture

All-in-one Next.js app

Route handlers, server actions and /admin inside the existing project. One build, one PM2 process, one nginx vhost. No CORS, no cross-origin session sharing.

Database

PostgreSQL + Prisma

JSONB stores localized fields natively; Prisma gives real migration files, which matters when altering schema on a live server.

Localization

Russian required, other four optional with fallback

A product ships the moment its Russian copy exists. Empty locales fall back to ru, so the site never renders a blank field and translations can be backfilled at leisure.

Carousels

Slide table referencing a product, with image override

Dedicated admin screen with drag-to-reorder. Name, roast and acidity read live from the product; the optional image override preserves today's behaviour where the carousel shows different art than the product card.

Descriptions

Per-product, optional, falls back to the shared string

All 16 products currently share one paragraph — including the tea, which is described as coffee. Optional per-product copy fixes that incrementally without blocking launch on writing 21 paragraphs.

Notifications

Gmail SMTP + WhatsApp Cloud API, both feature-flagged

Every submission is written to Postgres first, so a failed send never loses a lead. WhatsApp ships behind WHATSAPP_ENABLED and switches on by env var once Meta approves the message template — no code change.

Auth

Hand-rolled sessions stored in Postgres

argon2 hashes, signed httpOnly cookie, revocable session rows. Avoids betting the admin on Auth.js v5 beta compatibility with a Next release this new.

Media

Disk outside the repo, served by nginx

/var/www/nesilcoffee/uploads survives every git operation and redeploy. sharp converts to webp and generates the blur placeholder at upload, stored on the media row.

Rendering

Cached reads, invalidated on save

Pages stay as fast as they are today. Every mutation calls revalidateTag for what it touched, plus a manual purge button in admin as a backstop against stale content.

Cache API

unstable_cache, not Cache Components

Enabling cacheComponents: true would change prerendering across all 20 existing pages at once. Tag invalidation works identically on the current config; migrating is a separate post-launch task.

Orders

Read-only submissions log with CSV export

No statuses or notes. The site shows no prices and the FAQ states terms are negotiated individually — these are leads worked out of email, and the database is the safety net.

Deletion

Active toggle plus soft delete

Seasonal products get hidden, not deleted and re-typed in five languages. Carousel slides pointing at a hidden or deleted product are flagged in admin and skipped on the site rather than crashing it.

Spam

Honeypot, per-IP rate limit, submission timing

Invisible to real users and adds no third-party script to a site that currently loads zero. Suspected spam is stored and flagged rather than silently dropped.

Data model

Every localized field is Json shaped { ru, en?, tk?, uz?, az? }, read through one pick(field, locale) helper that falls back to ru.

// ---- Content -------------------------------------------------

model Category {
  id         String    @id @default(cuid())
  slug       String    @unique          // bean | instant | freeze-dried | tea
  name       Json                     // localized
  sortOrder  Int       @default(0)
  isActive   Boolean   @default(true)
  deletedAt  DateTime?
  products   Product[]
}

model Product {
  id           String    @id @default(cuid())
  slug         String    @unique          // reserved for detail pages
  name         Json
  description  Json?                    // null -> products.cardDescription
  tagline      Json?                    // null -> home.products.tagline
  weight       String                     // "1000 гр" — display string
  arabica      String?                    // "65%" | null
  robusta      String?
  roast        Int                        // 1..5
  acidity      Int                        // 1..5
  imageId      String?
  image        Media?    @relation(fields: [imageId], references: [id])
  categoryId   String
  category     Category  @relation(fields: [categoryId], references: [id])
  sortOrder    Int       @default(0)
  isActive     Boolean   @default(true)
  deletedAt    DateTime?
  homeSlides       HomeSlide[]
  productsSlides   ProductsHeroSlide[]
  @@index([categoryId, sortOrder])
}

model HomeSlide {
  id               String   @id @default(cuid())
  productId        String
  product          Product  @relation(fields: [productId], references: [id])
  imageOverrideId  String?                  // carousel art != card art
  sortOrder        Int
  isActive         Boolean  @default(true)
}

model ProductsHeroSlide {
  id              String   @id @default(cuid())
  productId       String?
  title           Json
  body            Json
  ctaLabel        Json?
  bgImageId       String
  productImageId  String?
  overlayColor    String                    // "#245314"
  overlayOpacity  Int                       // 40 -> /40
  productWidth    String                    // "38%"
  sortOrder       Int
  isActive        Boolean  @default(true)
}

model TeamMember {
  id         String    @id @default(cuid())
  name       Json
  role       Json
  phone      String?
  email      String?
  avatarId   String?                        // today all 5 share one image
  sortOrder  Int
  isActive   Boolean   @default(true)
  deletedAt  DateTime?
}

model FaqItem     { id, question Json, answer Json, sortOrder, isActive, deletedAt }
model Certificate { id, name Json, description Json, imageId, sortOrder, isActive, deletedAt }

model Setting {                            // singleton, id = 1
  id         Int     @id @default(1)
  phones     Json                          // ["+993 137 32969", …]
  email      String
  address    Json                          // localized
  instagram  String?
  tiktok     String?
  whatsapp   String?
}

// ---- Media ---------------------------------------------------

model Media {
  id           String   @id @default(cuid())
  path         String                        // /uploads/products/2026/xk3f9a.webp
  width        Int
  height       Int
  blurDataUrl  String   @db.Text             // generated by sharp on upload
  mimeType     String
  bytes        Int
  alt          Json?
  createdAt    DateTime @default(now())
}

// ---- Admin ---------------------------------------------------

model AdminUser {
  id            String         @id @default(cuid())
  email         String         @unique
  passwordHash  String                        // argon2id
  name          String
  role          Role           @default(EDITOR)
  createdAt     DateTime       @default(now())
  sessions      AdminSession[]
}

model AdminSession {
  id         String    @id @default(cuid())
  tokenHash  String    @unique                // raw token only ever in the cookie
  userId     String
  user       AdminUser @relation(fields: [userId], references: [id], onDelete: Cascade)
  expiresAt  DateTime
  ip         String?
  userAgent  String?
  createdAt  DateTime  @default(now())
  @@index([userId])
}

// ---- Inbound -------------------------------------------------

model Submission {
  id                String         @id @default(cuid())
  type              SubmissionType                // CONTACT | ORDER
  name              String
  email             String?
  phone             String?
  subject           String?
  message           String?        @db.Text
  productId         String?                       // ORDER only
  quantity          Int?
  locale            String
  ip                String?
  userAgent         String?
  isSpam            Boolean        @default(false)
  notifiedEmail     Boolean        @default(false)
  notifiedWhatsapp  Boolean        @default(false)
  createdAt         DateTime       @default(now())
  @@index([createdAt])
}

model RateLimit { key String @id, count Int, windowEnd DateTime }

enum Role           { ADMIN EDITOR }
enum SubmissionType { CONTACT ORDER }

Two Next 16 traps

Found by reading node_modules/next/dist/docs — both would have produced code that looked right and behaved wrong.

Renamed convention

middleware.ts is deprecated — it is now proxy.ts

Your existing file still runs, but the named export and filename are both on a deprecation path. More importantly, the proxy documentation states plainly that authentication must be verified inside each server function rather than relying on the matcher, because a matcher edit can silently remove coverage. Admin auth therefore lives in the layout and in every action, and the proxy is left to next-intl alone.

Divergent APIs

Two caching models ship in parallel

Projects with cacheComponents: true use 'use cache', cacheTag and cacheLife; projects without it use unstable_cache. Yours is the latter. revalidateTag also now takes a second argument controlling the stale-while-revalidate window — calls written from memory omit it.

Open items

Nothing here blocks phases 1 through 6. All of it is needed before phase 7 goes live.

Needs you

Two-factor authentication on the Gmail account

Google only offers App Passwords once 2-step verification is on, and SMTP will not authenticate without one. Roughly two minutes at myaccount.google.com, but email notifications cannot be tested until it is done.

Lead time

WhatsApp message template approval

Business-initiated messages require a template reviewed by Meta, typically about a day. The number used also cannot already be registered on regular WhatsApp. The feature flag means this never blocks a release.

Content

Team photographs

All five team members currently render the same avatar and the same name, role, phone and email in every language. The schema gives each member their own photo — the images themselves still need supplying.
